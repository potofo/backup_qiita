# Product Overview

Qiita記事バックアップツール — 自分のQiita全記事(限定共有記事を含む)のMarkdownと画像を、
Qiita API v2(個人用アクセストークン)経由でローカルPCへバックアップするローカルWebツール。
ローカルで執筆・編集した記事をQiitaへ反映する**アップロード同期**(明示操作限定)にも対応する。

## Core Capabilities

- **全記事バックアップ**: 記事本文(raw Markdown)+記事内画像をローカルへ保存。
  閲覧用Markdown(画像参照を相対パスに書換)と原本(`original.md`)の2形態で保持
- **状態管理と差分検出**: 全記事を8状態(未バックアップ/最新/Qiita側更新/ローカル改変/
  ローカル新規/競合/ローカル欠落/Qiita側削除)に分類し、
  差分(既定)・全件・選択の3モードでバックアップを実行
- **アップロード同期(ローカル→Qiita)**: `backups/` 内で新規作成した記事の登録
  (常に限定共有=非公開)と、ローカル編集した既存記事の本文更新。
  変更点全件・選択の2モード、実行前確認必須、競合記事は保護
- **世代管理**: `backups/` 配下の独立Gitリポジトリへ実行単位でコミット(`backup` ブランチ固定、ローカル専用)
- **進捗の可視化**: プログレスバー・記事単位の結果ログ・キャンセル。完了後は結果サマリと実行履歴
  (Run方向: バックアップ/アップロード)を表示

## Target Use Cases

- Qiita執筆者が自分の記事資産(特に限定共有記事)を手元に確保しておきたい
- Qiita側の更新を検知して差分だけを取り直したい
- ローカルのエディタで記事を執筆・推敲し、Qiitaへ非公開のまま登録したい
- バックアップの世代(いつ・何を取ったか)をGit履歴として遡りたい

## Value Proposition

- **ローカル完結**: 認証情報も記事データもQiita以外の外部サービスへ送信しない。
  Webサーバはループバック(127.0.0.1)のみで待ち受ける
- **事故の構造的防止**: バックアップリポジトリはリモート登録なし+pre-pushフックで
  `backup` ブランチのpushを拒否 — 限定共有記事の誤公開を仕組みで防ぐ
- **書き込みは明示操作のみ**: バックアップは読み取り専用(`read_qiita` のみで利用可)。
  Qiitaへの書き込みは実行前確認を経たアップロード操作に限定し、自動同期・削除は行わない。
  新規記事は常に限定共有(非公開)で登録され、公開はQiita上でユーザ自身が行う
