# セキュリティ標準

本プロジェクト(ローカル完結のQiitaバックアップツール)のセキュリティ規律。
要件上の根拠は外部要件書の N-SEC-01〜05 / F-AUTH-05〜08。

## 原則

- **最小権限**: スコープは利用機能に応じた最小構成とする(下記「スコープ方針」)。
  不要な書き込み権限を要求しない
- **ローカル完結**: 認証情報・記事データを Qiita 以外の外部サービスへ送信しない
- **フェイルクローズ**: トークン無効・設定不備は処理を止めて案内を出す(黙って続行しない)

## スコープ方針(article-upload-sync)

- **バックアップのみの利用**: `read_qiita` のみ(従来どおり。書き込み権限を必須にしない)
- **アップロード機能も使う場合**: `read_qiita` + `write_qiita`
- Qiitaへの書き込み(POST/PATCH)は**明示的なユーザ操作によるアップロードに限定**する。
  自動同期・定期実行は行わず、DELETEは実装しない
- 新規記事は常に**限定共有(`private: true`)**で登録する(誤公開の構造的防止)。
  公開操作はQiita上でユーザ自身が行う
- スコープ照会APIが存在しないため、書き込み権限は実績ベース(成功→可 / 403→不可)で管理し、
  「不可」既知の場合はアップロードを開始前に拒否する

## アクセストークンの取り扱い

- 保存場所は `.env` の `QIITA_ACCESS_TOKEN` のみ。コード・設定JSON・ログに書かない
- メモリ上で保持し、永続化は F-AUTH-08(ユーザ同意による `.env` 保存)の1経路に限定する
- `.env` へ書き込む際は該当キーの行だけを更新し、他のキーやコメントを破壊しない
- 表示が必要な場合は **末尾4桁のみのマスク表示**(例: `****8d5a`)。入力欄はパスワード型
- 漏洩を疑ったら即失効(Qiita設定画面で削除)→再発行を案内する

## ブラウザセッションの取り扱い(image-upload-automation)

- 画像アップロード機能のブラウザセッション(Cookie等)は、トークンに次ぐ**2つ目の秘密情報**として扱う
- 既定では保存しない: 一時プロファイルを使い、Run終了時に削除する
- 利用者が同意した場合のみ `.image-upload/browser-profile/` に保存する(`.gitignore` 対象・`backups/` の外)。画面から削除できる
- Cookie・ストレージの値をツールが読まない・ログに出さない。ID・パスワードは扱わない(ログインは利用者がブラウザ上で行う)
- ブラウザ操作部品にアクセストークンを渡さない(APIトークンとブラウザセッションは独立)

## 認証ヘッダの送信先制限

```javascript
// Authorization ヘッダは qiita.com へのAPIコールにのみ付与する
const isQiitaApi = (url) => new URL(url).host === "qiita.com";
```

- 画像取得先(`camo.qiitausercontent.com`、`qiita-image-store.s3.*`)は認証不要。
  **HTTPクライアントを共有して認証ヘッダが漏れる実装を禁止**(N-SEC-05)
- 画像URL以外の外部URLへの自動アクセスは行わない

## ネットワーク境界

- Webサーバは **ループバックアドレス(127.0.0.1 / localhost)のみ**で待ち受ける(N-SEC-03)
- 外部公開・LAN公開のオプションは設けない

## リポジトリ衛生

- ツール本体リポジトリ: `.env` と `backups/` を `.gitignore` に含める。`.env.example`(値なし)を同梱
- バックアップリポジトリ(`backups/.git`): **リモート登録・push/pull を行わない**(F-GIT-02)。
  限定共有記事(`private: true`)が誤って公開される事故を構造的に防ぐ
- コミット先は `backup` ブランチ固定(F-GIT-08)かつローカル専用。pre-pushフックを自動設置し、
  手動操作を含む `backup` ブランチのpushを拒否する(F-GIT-09)。ユーザ独自のフックは上書きしない
- 限定共有記事のバックアップはローカルにのみ存在する前提でUI文言を書く

## ログ規律

- 出力してよい: リクエスト先URL(クエリまで)、HTTPステータス、記事ID、処理結果
- 出力禁止: トークン全文、`Authorization` ヘッダ、レスポンスボディ全文
- エラーログには記事IDと失敗理由を含め、原因調査可能にする(N-OPS-01)

## 起動時検証

- 起動時に `.env` を読み込み、必須値の欠落は警告表示(トークンは画面入力で補完可能なため即終了はしない)
- `BACKUP_DIR` が想定外の場所(システムディレクトリ等)を指す場合は書き込み前に拒否する
