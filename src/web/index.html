新規記事の作成規約(ローカル→Qiitaアップロード)

バックアップフォルダ(backups/)直下に任意名のフォルダを作り、その直下に Markdownファイル(.md)を1つ置いてください。ファイル先頭に次のfrontmatterが必要です:

---
title: 記事のタイトル
tags: [tag1, tag2]
---
ここから本文を書きます。
  • title(必須): 記事のタイトル
  • tags(必須・1件以上): [a, b] / a b c(スペース区切り)/ - タグ名 の行区切り のいずれか

アップロードされた新規記事は限定共有(非公開)として登録されます。公開はQiita上で行ってください。登録成功後、フォルダは既存記事と同じ構成(タイトル_記事ID)へ自動変換されます。

実行履歴

アップロード内容の確認

新規記事は限定共有(非公開)として登録されます。アップロードによって記事が公開されることはありません。公開はQiita上で行ってください。

  • アップロードした画像は、URLを知っている人なら誰でも閲覧できます(限定共有の記事でも同じです)。
  • Qiitaの画像アップロード容量を消費します。
  • 画像の投入のため、Qiita上に作業用の下書きが1件残ります(削除はQiita上でご自身で行ってください)。
  • 実行するとブラウザが開きます。Qiitaにログインしていない場合は、開いたブラウザでログインしてください。

画像の自動アップロードを有効にする前に

  • Qiita API には画像をアップロードする手段がないため、この機能はQiitaのエディタ画面をブラウザで自動操作する非公式な方法で画像をアップロードします。
  • Qiitaの画面が変更されると、予告なく動作しなくなることがあります。その場合は処理を止め、手動での画像アップロード手順を案内します。
  • Qiita利用規約に自動化ツールを直接禁止する条項はありませんが、第11条(禁止事項)・第12条(アカウントの凍結・削除)に照らして問題と判断された場合、アカウントが凍結される可能性があります。ご自身の判断でご利用ください。
  • ログインは開いたブラウザでご自身で行います。ツールはID・パスワードを扱いません。記事の保存・投稿・公開は画面上で一切行いません。
